# LSS to Foundry

Модуль для Foundry VTT: импорт персонажей из Long Story Short (LSS) в Foundry VTT (dnd5e).

Этап 1. Установка через манифест опубликованного релиза или вручную (см. ниже).

## Что делает

- Читает файлы персонажей LSS (`.json`) и создаёт в мире Foundry персонажа dnd5e.
- Характеристики, владения, HP, ячейки заклинаний и бонусы переносятся так, чтобы итоговые числа листа совпадали с LSS.
- Класс, подкласс, вид, предыстория и SRD-заклинания берутся из компендиумов dnd5e, а не копируются. Тексты LSS в модуль не попадают.
- Свои заклинания из Гримуара LSS создаются в мире один раз, а персонажи получают их копии.
- Файлы читаются в браузере. Модуль никуда ничего не отправляет.

## Требования

- Foundry VTT 13. Целевая сборка — 13.348.
- Система dnd5e 5.1.x. Целевая версия — 5.1.8.
- Рекомендуется Babele и модуль перевода `ru-ru` (см. раздел «Перевод заклинаний»).

### Статус совместимости

Бейджи автоматически читают поля `minimum` и `verified` из `module.json` ветки `main`. Это декларация манифеста, а не результат тестирования в запущенной Foundry. Данные могут отображаться с задержкой из-за кеширования Shields.io.

| Foundry | dnd5e | Статус |
|---|---|---|
| 12 и ниже | любые | Ниже минимальной версии модуля; поддержка не заявлена |
| 13.348 | 5.1.8 | Целевая комбинация; требуется проверка полного импорта в живом мире |
| Другие сборки и поколения | другие версии | Совместимость не подтверждена тестовым прогоном |

Текущие тесты Vitest проверяют преобразование данных и взаимодействие с подменёнными объектами Foundry. Они не подтверждают загрузку модуля, валидацию документов настоящей системой dnd5e, работу компендиумов и интерфейса. Чек-лист проверки в живом мире: [docs/QA.md](docs/QA.md).

Для автоматической проверки совместимости нужна матрица конкретных пар Foundry + dnd5e. В каждой паре тестовый сервер запускается с отдельным временным каталогом данных и тестовым миром, затем браузерный тест открывает мир, импортирует эталонных персонажей 2014/2024 и проверяет созданные Actor/Item, HP, навыки, атаки, заклинания, открытие листа и ошибки модуля. Проверять нужно ожидаемые итоговые значения, а не только отсутствие исключений. Отдельный сценарий добавляет Babele и перевод. Результат относится к этим версиям и сценариям; совместимость со всеми сторонними модулями он не гарантирует.

Такой прогон пока не настроен. Для него потребуются дистрибутивы выбранных версий Foundry и доступ к лицензированной тестовой установке; официальный Node.js-сервер описан в [руководстве установки Foundry](https://foundryvtt.com/article/installation/). Дистрибутивы и ключи не публикуются в репозитории. Тестовые миры изолируются от пользовательских данных, а сборки, использующие одну лицензию, запускаются последовательно. При публикации можно блокировать релиз по обязательным комбинациям, а для экспериментальных версий показывать отдельный статус.

## Установка
1. Копируем ссылку:
```text
https://github.com/Dezodemius/lss-to-foundry/releases/latest/download/module.json
```
2. Вставляем в Foundry <img width="929" height="106" alt="image" src="https://github.com/user-attachments/assets/46903a87-73a9-486f-aabd-6a59e6329ba9" />


Для ручной установки:

1. Скопируйте папку модуля в каталог модулей данных Foundry: `<Data>/modules/lss-to-foundry`. Имя папки должно совпадать с id модуля `lss-to-foundry`. Пример пути данных: `F:/Files/Foundry VTT/UserDate/Data`, тогда папка будет `F:/Files/Foundry VTT/UserDate/Data/modules/lss-to-foundry`.
2. Вместо копии можно создать ссылку (на Windows, в командной строке от имени пользователя):
   `mklink /J "F:\Files\Foundry VTT\UserDate\Data\modules\lss-to-foundry" "F:\LongStoryShort\lss-to-foundry"`.
   Foundry подгружает скрипты, стили и переводы по `module.json`. Служебные папки (`node_modules`, `test`, `docs`, `.git`) ей не нужны. Как Foundry ведёт себя при ссылке на весь репозиторий, не проверялось. Для чистой копии достаточно `module.json`, `scripts`, `styles`, `templates`, `lang` и `data`.
3. В Foundry откройте «Управление модулями» и включите «LSS to Foundry» в нужном мире.

## Как получить файлы из LSS

- **Персонаж.** Нужен файл персонажа LSS в формате `.json` (внутри `"jsonType": "character"`). В документации LSS не описано, где в интерфейсе его скачать. Используйте файл, который уже выгружен из LSS.
- **Гримуар (свои заклинания).** В Гримуаре нажмите кнопку «.json», затем «Скачать .json» (раздел «Экспорт заклинаний» в документации LSS). Файл можно выбрать в окне импорта вместе с персонажами.

## Как импортировать

1. На вкладке «Актёры» боковой панели нажмите «Импорт из LSS». Кнопка видна, если у вас есть право создавать актёров.
2. Выберите один или несколько файлов `.json`. Под списком появятся персонажи с чекбоксами. Все отмечены по умолчанию. Предупреждения раскрываются по клику.
3. Снимите отметки с лишних персонажей и нажмите «Импортировать».
4. В отчёте по каждому персонажу видно, создан он или нет. Для созданного есть кнопка «Открыть лист». Отчёт также показывает предупреждения, заклинания, которых не нашлось в компендиумах, и заклинания, созданные из Гримуара.

Если редакция персонажа (2014 или 2024) не совпадает с правилами мира (настройка dnd5e «Правила»), окно предупредит об этом. Импорт при этом выполняется, но числа и предметы могут отличаться.

## Настройки

Настройки находятся в «Настройках игры», в разделе модуля «LSS to Foundry»:

- **Папка актёров** (по умолчанию `LSS`). Пустое значение означает корень.
- **Папка своих заклинаний** (по умолчанию `LSS: Гримуар`).
- **Особенности классов и видов** (включено). Добавляет особенности класса, подкласса, вида и предыстории, доступные на текущем уровне.
- **Аватар из LSS** (включено). Портрет из файла становится изображением актёра и токена.
- **Дополнительные компендиумы заклинаний**. ID компендиумов через запятую, например `world.my-spells`. Ищутся раньше стандартных компендиумов dnd5e.

## Что переносится и что нет

Переносится:

- характеристики с прибавками, владения навыками и спасбросками, HP (максимум, текущие, временные), КД, скорость, тёмное зрение, монеты;
- ячейки заклинаний и колдовство колдуна;
- класс, подкласс, вид, предыстория (ссылками на компендиумы dnd5e) и их особенности, если включена настройка;
- заклинания: SRD из компендиумов, свои из Гримуара;
- оружие и ресурсы (как предметы);
- бонусы LSS как эффекты, а также текст персонажа: предыстория, черты, идеалы, связи, пороки, внешность, заметки.

Не переносится или переносится частично:

- Выборы, которые требуют решения игрока (`ItemChoice`, увеличение характеристик, опциональные черты), не применяются. Они попадают в отчёт.
- Мультикласс. LSS хранит один класс, и импорт создаёт персонажа с одним классом.
- Бонусы, которые модуль не умеет перевести в эффект, пропускаются, и причина попадает в отчёт.
- Переводы и описания из LSS в модуль не включаются.

## Перевод заклинаний

Русские названия и описания заклинаний даёт Babele с модулем перевода `ru-ru`. Для этого язык мира должен быть русским.

- Заклинания редакции 2014 переводятся компендиумом `ru-ru`.
- Для редакции 2024 в `ru-ru` 13.348.1 перевода нет. В свежих версиях `ru-ru` (upstream, файл `ag/dnd5e.spells24.json`) он появился: обновите модуль. Без перевода заклинания 2024 останутся на английском.

Импорт ищет заклинания по английскому идентификатору, поэтому перевод на поиск не влияет.

## Ограничения этапа 1

- Каждый импорт создаёт нового актёра. Повторный импорт того же персонажа даст дубликат. Обновление существующих персонажей запланировано на этап 2.
- Мультикласс не переносится.
- Формат файла Гримуара в документации LSS не описан. Разбор написан защитно и на реальном файле ещё не проверен.
- Создание своих заклинаний в мире требует права создавать предметы (`ITEM_CREATE`). Без него заклинание кладётся прямо в персонажа.
- Модуль разрабатывался без запуска Foundry. Поведение в живом мире нужно проверить.

## Для разработчиков

### Автоматический релиз

Workflow `.github/workflows/release.yml` запускается при отправке любого тега в GitHub, включая имена с `/`. Коммит тега должен входить в историю `main`; иначе workflow завершится ошибкой без публикации. Работают обычные и аннотированные теги. Сам workflow должен уже присутствовать в отмечаемом коммите.

Пример из командной строки Windows после получения актуального `main`:

```bat
git switch main
git pull --ff-only
git tag 0.1.1
git push origin 0.1.1
```

После `npm ci` и успешных тестов workflow собирает `module.zip` с файлами модуля в корне архива и публикует его вместе с `module.json`. Имя релиза и поле `version` в обоих манифестах совпадают с тегом без преобразований. Поле `download` указывает на архив именно этого тега, `manifest` — на манифест последнего опубликованного релиза. Исходный `module.json` в Git при сборке не изменяется.

Имя тега произвольное, но для предсказуемого сравнения версий при обновлениях Foundry рекомендуется возрастающий числовой формат, например `0.1.1`. Каждый новый опубликованный релиз помечается `Latest`, независимо от имени тега; это относится и к тегам на старых коммитах из истории `main`.

Файлы загружаются в черновик до публикации. После сбоя загрузки можно повторить запуск workflow: существующий черновик будет дополнен. Опубликованный релиз не перезаписывается — для новой сборки нужен новый тег. Для ранее отправленного тега автоматического запуска задним числом нет. Одновременно отправляйте не более трёх тегов: GitHub не создаёт tag-push события при отправке более трёх тегов за раз.

Используется встроенный `GITHUB_TOKEN` с правом `contents: write`; отдельный секрет не нужен.

### Разработка

- `npm install`, затем `npm test` (Vitest). Тесты покрывают чистую логику в `scripts/core` и не требуют Foundry.
- `npm run build:spell-index` пересобирает индекс SRD-заклинаний (`tools/build-spell-index.mjs`).
- Структура:
  - `scripts/core/` — чистая логика без глобалов Foundry: разбор LSS, маппинг, заклинания, Гримуар;
  - `scripts/foundry/` — запись в мир: компендиумы, классы, заклинания, актёр, оркестратор `importer.mjs`;
  - `scripts/ui/` — окно импорта (`ApplicationV2`);
  - `scripts/main.mjs`, `scripts/settings.mjs` — точка входа, настройки, кнопка в боковой панели;
  - `templates/`, `styles/`, `lang/` — разметка, стили, переводы (`ru`, `en`);
  - `test/` — тесты Vitest и фикстуры LSS.
- Публичный API для других модулей и браузерного расширения: `game.modules.get('lss-to-foundry').api` содержит `parseLssFile`, `importCharacters(characters, grimoire, options, onProgress)` и `openImportApp`.
- Проектные документы: `docs/CONTEXT.md`, `docs/DESIGN.md`, исследования в `docs/research/`.
