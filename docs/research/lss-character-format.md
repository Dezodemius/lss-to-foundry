# Формат персонажа Long Story Short (LSS): инвентаризация для импортёра

Состояние на 22.10.2026. Исследование выполнено по публичным артефактам LSS (схема, пример, датасеты),
локальной документации Ратуши (`F:\LongStoryShort\Guildhall\docs`) и обратному конвертеру
Elfrey (локальная версия 1.7, dnd5e 4.x, `F:\Files\Foundry VTT\UserDate\Data\modules\elfrey-lss-converter\module.js`).
Вход в LSS не выполнялся, непубличные API не использовались.

## Метки источников

- **[схема]** — `character.schema.json` (live-схема, скачана 22.10.2026). Схема описывает только содержимое `data`.
- **[пример]** — `character-example.json` (валиден по схеме, проверено Ajv).
- **[док]** — локальная документация Ратуши (MDX). Может отставать от схемы. В `developers/changelog.mdx` сказано: при расхождении верна схема.
- **[changelog]** — `developers/changelog.mdx` (записи от 2026-08-18 и 2026-10-18).
- **[конвертер]** — `module.js` elfrey-lss-converter 1.7. Пути и поля относятся к dnd5e 4.x.
- **[валид]** — проверено Ajv 8.20 против `character.schema.json` (скрипт и вывод в scratchpad).
- **[не проверено]** — нет источника, или источники противоречат друг другу.

---

## 0. Ответы на главные вопросы

- **Собственный id персонажа LSS в файле: нет.** Его нет в envelope, в `data`, в примере и в выводе конвертера.
  Бэкенд id, скорее всего, имеет (документация упоминает `GET /character/:id`), но в файл он не попадает [док, схема].
  Для дедупликации повторного импорта в файле ключа нет (см. 1.4).
- **Полный закрытый enum таргетов бонусов: да, 119 значений** (раздел 2.6), плюс два открытых семейства по `pattern`:
  `weapon.<id>.attack` и `weapon.<id>.damage`. Схема включает в enum только «живые» таргеты; неиспользуемые
  семейства (`stat.modifier`, `hp.temp`, `carry` и др.) намеренно исключены [схема].
- **Несколько персонажей в одном файле:** не описано ни в документации, ни в схеме. Описан один объект персонажа
  с константой `jsonType: "character"`. Как выглядит файл с несколькими персонажами, неизвестно [не проверено].

## 1. Верхний уровень документа (envelope)

Файл персонажа — это объект верхнего уровня, в котором `data` — строка с JSON [док, пример конвертера].

| Поле | Тип | Смысл | Источник | Статус |
|---|---|---|---|---|
| `jsonType` | `"character"` (константа) | тип документа | [док], [конвертер] | подтверждено |
| `version` | `"2"` | версия формата файла | [док], [конвертер] (пишет `"2"`) | подтверждено |
| `edition` | `"2014"` или `"2024"`, по умолчанию `"2024"` | механическая редакция правил (ID датасетов, список заклинаний) | [док] | подтверждено док; в схеме и в примере отсутствует |
| `sheetEdition` | `"2014"` или `"2024"` | косметическая редакция печатного листа, не зависит от `edition` | [док] | подтверждено док |
| `spells` | объект | настройки книги заклинаний (см. ниже) | [док], [changelog 2026-10-18] | подтверждено |
| `spells.mode` | `"cards"` или `"text"` | режим отображения. Конвертер пишет `"text"` | [док], [конвертер] | подтверждено |
| `spells.prepared` | массив строк | известные/подготовленные заклинания (включая заговоры): id, слаг или имя | [док] | см. раздел 4 |
| `spells.book` | массив строк | только книга волшебника; в `book` лежит всё, в `prepared` — подготовленное из неё | [док] | см. раздел 4 |
| `spells.pending` | массив `{ slug, list }` (`list`: `"prepared"` или `"book"`) | слаги, которые сервер не нашёл. Пишет сервер; при повторном импорте можно оставить как есть | [changelog 2026-10-18] | подтверждено |
| `spells.granted` | массив `{ id, source }` | заклинания, выданные датасетом (вне лимита подготовленных). Пишет только визард; слаги не принимаются | [док] | подтверждено док |
| `spells.slotless` | массив строк (id) | заклинания, которые нельзя оплатить ячейкой | [док] | подтверждено док |
| `disabledBlocks` | объект | скрытые блоки листа. Ключи: `info-left`, `info-right`, `subinfo-left`, `subinfo-right`, `notes-left`, `notes-right`; значения — массивы | [док] | конвертер пишет только 4 ключа, без `subinfo-*` [конвертер] |
| `data` | строка (JSON) | всё содержимое листа (см. раздел 2) | [док], [схема] | подтверждено |
| `tags` | массив (конвертер пишет `[]`) | назначение не описано | [конвертер] | не проверено |

Пример envelope из документации [док]:

```json
{
  "jsonType": "character",
  "version": "2",
  "edition": "2024",
  "sheetEdition": "2024",
  "spells": { "mode": "cards", "prepared": [], "book": [], "granted": [], "slotless": [] },
  "disabledBlocks": { "info-left": [], "info-right": [], "subinfo-left": [], "subinfo-right": [], "notes-left": [], "notes-right": [] },
  "data": "{ ...см. ниже... }"
}
```

### 1.1 Id и дедупликация

- Собственного id персонажа в файле нет (ни в envelope, ни в `data`, ни у конвертера) [схема, пример, конвертер].
- `data.createdAt` есть в схеме, но это read-only поле, которое бэкенд подставляет при `GET /character/:id`.
  При сохранении обратно оно ни на что не влияет [схема, док]. Ключом уникальности оно не является: в файлах конвертера его нет.
- Варианты для дедупликации [предложение, не проверено]:
  - хэш нормализованного `data` без `createdAt` (нормализация нужна, потому что файл меняется при редактировании);
  - сочетание `name.value`, `info.playerName.value`, `info.level.value` и `createdAt`;
  - id из аккаунта LSS, если список персонажей аккаунта доступен через публичный путь. Это вопрос к владельцу. Непубличные API не трогаем.

### 1.2 Несколько персонажей в одном файле

Не описано [док, схема]. Схема описывает один объект персонажа. Массив персонажей, пакет или иной контейнер
в документации не упомянуты. Для импортёра это значит: по умолчанию считать один файл = один персонаж,
а массив обрабатывать только после уточнения у владельца [не проверено].

[валид, пример: `isDefault`, `bonusesSkills`, `wizardStep`, `id`]. Обязательные корневые поля: `jsonType`, `name`, `info`, `stats`, `saves`, `skills` [схема].

### 2.1 Что значит `{ value: ... }`

Все редактируемые поля обёрнуты в `{ value: ... }`, если обратное не указано [док]. Исключения, которые видны
в схеме: `info.subrace` (только `id`/`value`), `info.size` (без поля `name`), `avatar`, `proficiency`, `stats`
(используется `score`), `bonuses` (массив).

### 2.2 `info`

| Поле | Тип | Обяз. | Смысл, id |
|---|---|---|---|
| `charClass` | `{ name: "charClass", value: string, id?: string }` | да | класс. `id` — голый id датасета (`cleric`, а не `srd-2024:cleric`) |
| `charSubclass` | `{ name: "charSubclass", value: string, id?: string }` | да | подкласс. `id` — голый id подкласса |
| `level` | `{ name: "level", value: number }` | да | уровень |
| `background` | `{ name: "background", value: string, id?: string }` | да | предыстория, `id` — голый id |
| `playerName` | `{ name: "playerName", value: string }` | да | имя игрока |
| `race` | `{ name: "race", value: string, id?: string }` | да | раса, `id` — голый id |
| `subrace` | `{ id?: string, value?: string }` | нет | вид/подвид; без обёртки `name` |
| `alignment` | `{ name: "alignment", value: string }` | да | мировоззрение (свободный текст) |
| `experience` | `{ name: "experience", value: number \| "" }` | да | опыт; `""` — значение по умолчанию у нового персонажа. Нельзя писать «34 000» |
| `size` | `{ value: "tiny" \| "small" \| "medium" \| "large" \| "huge" }` | нет | размер; влияет на переноску и т.п. Конвертер пишет top-level `size: 9`, что не соответствует схеме [конвертер, валид] |

Примеры [пример]: `charClass: { name: "charClass", value: "Cleric", id: "cleric" }`, `charSubclass: { name: "charSubclass", value: "Life Domain" }` (без id),
`race: { name: "race", value: "Human" }`, `size: { value: "medium" }`.

Правило идентификаторов: `info.*.id` и `spellsInfo.available.classes` — голые id датасета. Префикс источника
(`srd-2024:`) используется только в `bonuses[].source.refId` [схема, док].

### 2.3 `subInfo`

Все поля необязательны (объекты), каждое — `{ name: <ключ>, value: string }`: `age`, `height`, `weight`, `eyes`, `skin`, `hair`.
Значения свободного текста (пример: `age: "27"`, `height: "168 см"`).

### 2.4 `spellsInfo`

| Поле | Тип | Смысл |
|---|---|---|
| `base` | `{ name: "base", value: string, code: enum }` | характеристика каста. `code`: `str`, `dex`, `con`, `int`, `wis`, `cha` |
| `save` | `{ name: "save", value: string, customModifier: string \| null }` | сложность спасброска: `customModifier` — формула-переопределение (числовой контекст, см. раздел 3). `value` в примере пустой; назначение `value` не описано [не проверено] |
| `mod` | `{ name: "mod", value: string, customModifier: string \| null }` | бонус атаки заклинанием: то же, что `save` |
| `charges` | `{ [spellId]: resourceId }` | заклинание → счётчик (`data.resources`), которым оно оплачивается без ячейки |
| `abilities` | `{ [spellId]: "str" \| "dex" \| "con" \| "int" \| "wis" \| "cha" }` | характеристика, которой кастуется конкретное заклинание, если она не совпадает с `base.code` |
| `available` | `{ classes: string[], spells: string[] }` | дополнительные классы (голые id) и id заклинаний для выборки |

Пример [пример]: `base: { name: "base", value: "", code: "wis" }`, `save: { name: "save", value: "" }`, `mod: { name: "mod", value: "" }`.

Конвертер пишет `save.value` и `mod.value` числами (`v.spelldc`, `v.spellmod + v.prof`), а схема требует строку.
Ajv отклоняет число [валид, конвертер]. См. раздел 7.

### 2.5 `spells` и `spellsPact`

- Ключи: только `slots-0` … `slots-9` (шаблон `^slots-[0-9]$`), иные ключи не допускаются [схема, валид].
- `slots-0` — заговоры, ячеек не тратят, значение бессмысленное [схема].
- Значение круга: `{ value?: number, filled?: number }`. `value` — всего ячеек, `filled` — израсходовано. Отсутствие `value` = ячеек на этом круге нет [схема].
- `spellsPact` — то же, только для ячеек договора колдуна [схема].
- Пример [пример]: `spells: { "slots-1": { value: 4, filled: 1 }, "slots-2": { value: 2, filled: 0 } }`, `spellsPact: {}`.

Конвертер пишет `filled` равным `max` для всех кругов [конвертер]. По смыслу `filled` — израсходовано, так что это
похоже на ошибку конвертера. Pet2022 converter пишет, что ячейки корректны только при полном восстановлении [не проверено].

### 2.6 `bonuses` (единственный канал числовых бонусов)

Массив объектов `CharacterBonus` [схема, док]. Поля:

| Поле | Тип | Обяз. | Смысл |
|---|---|---|---|
| `id` | строка | да | уникальный id бонуса. Формат из примера: `bonus-<timestamp>-<random>` [пример] |
| `label` | строка | да | подпись |
| `target` | enum или pattern (см. ниже) | да | цель бонуса |
| `mode` | `add` \| `set` \| `upgrade` \| `downgrade` \| `multiply` \| `advantage` \| `disadvantage` | нет (в схеме не обязательно) | операция слоя. Заменяет устаревший `kind`. `advantage`/`disadvantage` не несут значения |
| `priority` | число | нет | порядок применения (меньше — раньше). По умолчанию выводится из `mode` через `DEFAULT_PRIORITY`. `'override'` сопоставляется с `LOCK_PRIORITY` |
| `kind` | `modifier` \| `override` | нет | устаревшее поле, оставлено в схеме |
| `value` | число | нет | числовое значение. Ровно одно из `value` или `expr` |
| `expr` | строка или `null` | нет | формула (числовой контекст, см. раздел 3) |
| `source` | `{ kind, refId?, label? }` | да | источник (см. ниже) |
| `disabled` | boolean | нет | временно отключить без удаления |
| `stackingType` | строка | нет | не описано [схема, не проверено] |
| `duration` | строка | нет | не описано [схема, не проверено] |
| `conditional` | `{ key: string, default?: boolean }` | нет | условие; `key` обязателен |

`source.kind` (закрытый enum, 11 значений): `user`, `origin`, `background`, `attunement`, `item`, `classFeature`,
`spell`, `feat`, `condition`, `effect`, `derived`. `source.refId` — id владельца (не нужен для `user`).
`source.label` — подпись. Бонус с `source.kind: "attunement"` работает только если соответствующий слот в `attunementsList`
отмечен (`checked: true`) [схема].

Пример [пример]:

```json
{ "id": "bonus-src-classFeature-life-domain-hp.max-0", "label": "Disciple of Life (доп. HP при исцелении)",
  "target": "hp.max", "mode": "add", "value": 3,
  "source": { "kind": "classFeature", "refId": "srd-2024:cleric-life-domain", "label": "Disciple of Life" } }
```

В примере `refId` равен `srd-2024:cleric-life-domain`, а id подкласса в датасете 2024 — `life-domain`. Конвенция
формирования `refId` не описана [не проверено].

#### 2.6.1 Полный закрытый enum таргетов (`target`)

Всего 119 значений в enum и два открытых семейства по `pattern` [схема, валид]. Скрипт проверки выдал те же 119 значений.

Группы (значения перечислены полностью):

- **AC, атака, проверки, урон, HP, инициатива, щит, заклинания (9):** `ac`, `attack.all`, `check.all`, `damage.weapon`, `hp.max`, `initiative`, `shield`, `spellAttack`, `spellDC`.
- **Ячейки (18):** `spellSlot.1` … `spellSlot.9`, `pactSlot.1` … `pactSlot.9`.
- **Пассивные (3):** `passive.insight`, `passive.investigation`, `passive.perception`.
- **Скорость (1):** `speed.walk`.
- **Спасброски (8):** `save.all`, `save.str`, `save.dex`, `save.con`, `save.int`, `save.wis`, `save.cha`, `save.cor` (`save.cor` — только для aime в данных, но в enum есть).
- **Владения спасбросками (7):** `prof.save.str`, `prof.save.dex`, `prof.save.con`, `prof.save.int`, `prof.save.wis`, `prof.save.cha`, `prof.save.cor`.
- **Владения доспехами и оружием (7):** `prof.armor-light`, `prof.armor-medium`, `prof.armor-heavy`, `prof.armor-label` (щит, устаревшее имя ключа), `prof.weapon-simple`, `prof.weapon-martial`, `prof.weapon-other`.
- **Навыки (20):** `skill.acrobatics`, `skill.animal handling`, `skill.arcana`, `skill.athletics`, `skill.deception`, `skill.history`, `skill.insight`, `skill.intimidation`, `skill.investigation`, `skill.medicine`, `skill.nature`, `skill.perception`, `skill.performance`, `skill.persuasion`, `skill.religion`, `skill.riddle`, `skill.shadow-lore`, `skill.sleight of hand`, `skill.stealth`, `skill.survival`.
- **Владения навыками (20):** те же 20 ключей с префиксом `prof.`: `prof.skill.acrobatics`, … `prof.skill.sleight of hand`, … `prof.skill.shadow-lore`.
- **Характеристики (26):** для каждой из `str`, `dex`, `con`, `int`, `wis`, `cha` — четыре цели `stat.<ab>.score`, `stat.<ab>.check`, `stat.<ab>.attack`, `stat.<ab>.damage` (24), плюс `stat.sha.score` и `stat.sha.check` (2).

Открытые семейства по `pattern`:

- `^weapon\..+\.attack$` — например, `weapon.<id>.attack`, где `<id>` берётся из `weaponsList[].id`. Связь с `weaponsList` схема не проверяет.
- `^weapon\..+\.damage$` — то же для урона.

Намеренно **не** входят в enum (объявлены, но не читаются листом, бонус на них «молчит») [схема, cmt]: `stat.modifier`, `hp.temp`, `vitality.darkvision`, `speed.other`, `attack.kind`, `damage.spell`, `proficiency`, `carry`.

Ключи навыков в целях содержат пробелы (`skill.animal handling`, `skill.sleight of hand`). Ключ `sleightOfHand` недопустим [схема, док].

### 2.7 `effects`

Именованный набор бонусов, который включается и выключается целиком (например, «Камень удачи», «Благословение»).
Числа лежат в обычных `bonuses[]` с `source: { kind: "effect", refId: <effect.id> }`.

| Поле | Тип | Обяз. | Смысл |
|---|---|---|---|
| `id` | строка | да | id |
| `name` | строка | да | название |
| `description` | строка | нет | описание |
| `disabled` | boolean | нет | выключен: его бонусы не считаются, их собственный `disabled` не меняется |
| `icon` | строка | нет | ключ набора иконок (`EffectIcon/constants.ts`, не в репозитории) |
| `tone` | `buff` \| `debuff` | нет | смысл, а не цвет |
| `ends` | `short-rest` \| `long-rest` | нет | когда эффект заканчивается |
| `shown` | boolean | нет | показывать как статус. Отсутствует — показывается; `false` — игрок скрыл |

### 2.8 `stats`

Ключи: `str`, `dex`, `con`, `int`, `wis`, `cha` — обязательны; `sha` — только для шаблонов aime [схема, док].

| Поле | Тип | Смысл |
|---|---|---|
| `name` | строка (обязательна) | ключ характеристики (`"str"`) |
| `score` | число | значение характеристики (не модификатор) |
| `bonuses` | массив `CharacterBonus` | бонусы, привязанные к характеристике (см. 2.6) |
| `shadowTemp` | число | только `sha`: временное значение |

Пример [пример]: `str: { name: "str", score: 13 }`.

Удалённые (вычисляются на чтении) поля: `modifier`, `check`, `total`, `extraBonusComputed`, `race`. Декомиссионированные: `origin`,
`extraBonusExpr`. Ранговые надбавки (ASI) выражаются бонусом `stat.X.score` с `source` = `origin` [схема].

### 2.9 `saves`

Ключи: `str`, `dex`, `con`, `int`, `wis`, `cha` — обязательны; `cor` — только aime [схема].

| Поле | Тип | Обяз. | Смысл |
|---|---|---|---|
| `name` | const (`"str"` и т.д.) | да | ключ |
| `isProf` | boolean или целое `0`, `1`, `2` | да | владение; `2` — экспертиза |
| `bonus` | число | нет | плоская надбавка (устаревшая, рядом с `bonuses[]`) |
| `bonusExpr` | строка | нет | формула-надбавка (числовой контекст) |
| `customModifier` | число или строка | нет | полное переопределение итога спасброска |

Пример [пример]: `str: { name: "str", isProf: false }`, `con: { name: "con", isProf: true }`.

### 2.11 `vitality`

Фиксированный набор полей (ключи не словарь) [схема]:

| Ключ | Тип | Обяз. | Смысл |
|---|---|---|---|

Формулы `speed`, `ac`, `shield.mod`, `initiative` вычисляются в числовом контексте: кости дают 0, строка `"16"` тоже работает [схема].

### 2.12 `attunementsList`

Массив объектов, все поля обязательны: `id` (строка, формат `attunement-<timestamp>`), `checked` (boolean — слот занят),
`value` (строка — название предмета, свободный текст) [схема, пример]. Бонус с `source.kind: "attunement"` учитывается
только при `checked: true` [схема].

### 2.13 `weaponsList`

Массив `RawWeapon` [схема]:

| Поле | Тип | Обяз. | Смысл |
|---|---|---|---|
| `id` | строка | да | id оружия, формат `weapon-<timestamp>` [пример]. На него ссылаются цели `weapon.<id>.attack/damage` |
| `name` | `{ value: string }` | да (с `value`) | название |
| `dmg` | `{ value: string }` | да (с `value`) | формула урона в нотации костей, например `"1к6+[STR]"` [пример] |
| `ability` | строка enum `str`/`dex`/`con`/`int`/`wis`/`cha`/`none` | нет | характеристика атаки |
| `isProf` | boolean | нет | владение |
| `dmgType` | `{ value: string }` | да (с `value`) | тип урона, например `"дробящий"` [пример] |
| `notes` | `{ value: string }` | да (с `value`) | заметки |
| `notesVisibility` | boolean | нет | показывать заметки |
| `modCustom` | `{ value: number \| null }` | да (с `value`) | устаревший ручной модификатор атаки. Принимается при импорте, переносится в `modBonus` при загрузке (`migrateWeaponModCustom`) [схема] |
| `modBonus` | `{ value: number \| null }` | да (с `value`) | плоский бонус атаки (устаревший канал, пока не конвертирован) |

Производные поля (не писать): `mod`, `damageBonus`, `damageRoll`, `displayDamage`, `damageDisplay`, `hasAttackOverride`, `hasDamageOverride` [схема].

Конвертер пишет `mod: { value: "+N" }` и не пишет `modBonus`. Поле `mod` схемой не допускается [конвертер, валид].

Пример [пример]: `{ "id": "weapon-1780000000002", "name": { "value": "Булава" }, "dmg": { "value": "1к6+[STR]" }, "ability": "str", "isProf": true, "dmgType": { "value": "дробящий" } }`.

### 2.14 `text`

Словарь блоков; ключ — id блока, задаётся шаблоном [схема, док]. Значение блока:

- `value` — объект, закрытый, с одним обязательным полем `data` (документ Tiptap/ProseMirror). Поле `value.id` в схеме не допускается [схема, валид].
- `size` — подсказка раскладки шаблона, необязательна [схема].
- `customLabel` — строка; `isHidden` — boolean [схема].

Минимально валидный документ [док]:

```json
{ "type": "doc", "content": [{ "type": "paragraph", "content": [{ "type": "text", "text": "..." }] }] }
```

**Ключи блоков.** Часто встречаются (по описанию схемы): `attacks`, `weapons`, `traits`, `feats`, `equipment`, `attunement`,
`prof`, `personality`, `ideals`, `bonds`, `flaws`, `features`, `background`, `quests`, `allies`, `appearance`, `notes-1` … `notes-6`,
`items` [схема]. Конвертер дополнительно пишет `spells-level-0` … `spells-level-9` (тексты заклинаний в текстовом режиме) [конвертер].

**Узлы документа.** Документация перечисляет `paragraph`, `text`, `bulletList`, `orderedList`, `listItem`, `roller`, `formula`,
`resource`, `divider`, `spoiler`, `spoilerSummary`, `spoilerContent`, `taskList`, `taskItem` [схема, док].
`blockquote` в редакторе не зарегистрирован и не допускается. Нераспознанный тип узла роняет рендер всего текстового блока
(в редакторе нет error boundary) [док, схема]. Эта ошибка дорогая для генератора, поэтому импортёру нужен белый список узлов.

Атрибуты узлов:

- `resource` — `attrs: { id, textName }`. Подтверждено примером и конвертером [пример, конвертер].
- `text` — `text` и `marks` (массив `{ type: "bold" \| "italic" \| "underline" \| "link", ... }`). Подтверждено конвертером
  для bold, italic, underline [конвертер, схема].
- `roller`, `formula`, `divider`, `spoiler`/`spoilerSummary`/`spoilerContent` (вкл. теги блоков, цвет принадлежит тегу), `taskList`/`taskItem`:
  атрибуты в схеме не валидируются, в документации не описаны [схема, док, не проверено]. Теги спойлеров хранятся
  где-то в атрибутах блока, но документация не говорит где.

Как писать формулы в тексте: docs/text-editor/dice-roller.mdx описывает включение формулы через выделение и Ctrl+D,
но атрибуты узла не приводит [не проверено].

### 2.15 `coins`

Закрытый объект: `gp`, `sp`, `cp`, `pp`, `ep`, каждый `{ value: number }` (обязательно `value`). `total` — вычисляется, не писать [док, схема].
Для шаблонов aime используются три номинала (`gp`/`sp`/`cp`), а не пять [схема].

### 2.16 `resources`

Объект, ключ — id ресурса. Совпадение ключа и `id` ожидается, но не проверяется схемой [схема].

| Поле | Тип | Обяз. | Смысл |
|---|---|---|---|
| `id` | строка | да | id, формат `resource-<timestamp>` [пример, конвертер] |
| `name` | строка | да | название |
| `current` | число | да | текущее значение (не больше максимума) |
| `max` | число | нет | максимум. Ровно одно из `max` или `maxExpr` [схема, док] |
| `maxExpr` | строка или `null` | нет | формула максимума (числовой контекст) |
| `location` | строка | нет | ключ блока `text`, в котором лежит узел `resource` [схема, пример] |
| `isShortRest` | boolean | нет | восстанавливается на коротком отдыхе |
| `isLongRest` | boolean | нет | восстанавливается на длинном отдыхе |
| `shortRestRegain` | строка или `null` | нет | формула, сколько возвращает короткий отдых. `null` или отсутствие = полное восстановление [схема] |

Не писать: `resolvedMax`, `resolvedShortRegain` (вычисленные; старые персонажи могут их содержать) [схема].

Пример [пример]: `{ "id": "resource-1780000000010", "name": "Channel Divinity", "current": 1, "max": 1, "location": "traits", "isShortRest": false, "isLongRest": true }`.

Конвертер пишет `icon` как `"short-rest"`, `"long-rest"` или `""` и выбирает `isLongRest` по `uses.per` из списка

Счётчик заклинания (`spellsInfo.charges`) тоже указывает на id ресурса [схема].

## 3. Формулы

### 3.1 Два контекста вычисления

**Числовой контекст** (`evaluateExpression`, mathjs). Поля: `bonuses[].expr`, `stats.*.bonuses[].expr`, `saves.*.bonusExpr`
и `customModifier`, `skills.*.bonusExpr` и `customModifier`, `spellsInfo.save.customModifier`, `spellsInfo.mod.customModifier`,
`vitality.speed/ac/initiative/shield.mod`, `resources.*.maxExpr` и `shortRestRegain` [схема].
- Переменные **строго в верхнем регистре**: `[STR]`, `[DEX]`, `[CON]`, `[INT]`, `[WIS]`, `[CHA]` (модификаторы характеристик, не значения), `[PROF]`, `[LVL]`.
  Нижний регистр не сопоставляется с переменной и даёт 0 без ошибки [схема, док characters.mdx].
- Кости в этом контексте не обрабатываются: `1d6` даёт 0 [схема].
- Функции: математика mathjs (`floor`, `ceil`, `round`, `abs`, `min`, `max` и др.) [схема, док expression-input.mdx].
- Примеры: `10+[DEX]`, `round([PROF]/2)`, `floor([LVL]/2)+[PROF]`.

**Костевой контекст** (пакет `@tldrpg/dice`, `prepareSheetFormula`). Поля: `weaponsList[].dmg.value`, формулы в текстовых блоках
(`roller`, `formula`), бонусы-кости в документации (пример `+1d4` от благословения) [схема, док notation.mdx].
- Переменные регистронезависимые: `[str]` = `[STR]`. Единственное исключение из правила «строчные не работают»
  в числовых полях — урон оружия [схема, док characters.mdx].
- Нотация: `NdS`, буква кости `d`, `D`, `к` или `К` (кириллица равноправна), `d%`, `dF`, `(выражение)d(выражение)`.
  Подробно — в разделе 3.2.

**Противоречие.** `notation.mdx` говорит, что в системе бонусов есть бонусы-кости (`+1d4` от благословения), а
`bonuses[].expr` по схеме вычисляется численно, и кости там дают 0. Как именно движок обрабатывает `expr` с костями, не проверено.

### 3.2 Нотация костей (общая для листа и Anima)

Источник: `docs/_shared/notation/_*.mdx`, `docs/character-sheet/notation.mdx`.

- Кости: `1d20`, `d20`, `2к6`, `3К8`, `d%`, `dF`; количество может быть выражением: `(ceil([LVL]/2))d6`, `max(1,[WIS])d8`. Отрицательное количество → 0 костей.
- Модификаторы после кости: `khN`, `klN` (оставить N старших/младших), `dhN`, `dlN` (отбросить), `!`, `!!`, `!p` (взрыв),
  `r`, `ro` + условие (перебросы), `u`, `uo` (перебрасывать повторы), `minN`, `maxN`, `cs`, `cf` + условие (крит), `sa`, `sd` (сортировка),
  условие (подсчёт успехов, `f` для провалов).
- Математика: `+`, `-`, `*`, `/`, `%`, `^`; функции `floor`, `ceil`, `round`, `min`, `max`, `abs`, `pow`, `sqrt`, `sign`, `exp`, `log`, `sin`, `cos`, `tan`.
- Группы: `{1d20, 1d20}kh1`, `{4d6, 2d6}>=6`, подписи частей `{1d12 (Надежда), 1d12 (Страх)}`.
- Условие: `if(условие, тогда, иначе)`, в условии нельзя бросать кости; операторы сравнения и `and`, `or`, `not`.
- Подписи: перед формулой (`Вдохновение барда 1d6`), в скобках в конце (`1d20+5 (Атака)`), после `#` (`1d100cs<=25 # Слишком медленный жест`).
  Слова сразу после формулы в урон-полях тоже подписи (`1к6 колющий`).
- Ограничения: до 1000 символов, до 32 уровней скобок, до 1000 костей, до 100 перебросов на кость.
  `//` и `/* */` — не комментарии.
- Итог броска округляется вниз. Крит — только на d20 атаки, проверки и спасброска [док].

### 3.3 Где в персонаже встречаются формулы

- `bonuses[].expr`, `stats.*.bonuses[].expr` — числовой контекст.
- `saves.*.bonusExpr`, `saves.*.customModifier`, `skills.*.bonusExpr`, `skills.*.customModifier` — числовой контекст.
- `spellsInfo.save.customModifier`, `spellsInfo.mod.customModifier` — числовой контекст.
- `vitality.speed.value`, `vitality.ac.value`, `vitality.shield.mod`, `vitality.initiative.value` — числовой контекст.
- `resources.*.maxExpr`, `resources.*.shortRestRegain` — числовой контекст.
- `weaponsList[].dmg.value` — костевой контекст.
- Узлы `roller` и `formula` в `text.*.value.data` — костевой контекст, атрибуты не описаны [не проверено].

Примеры из фикстуры: `ac: "10+[DEX]"`, `shield.mod: "2"` (без знака), `dmg: "1к6+[STR]"`, `dmg: "1к8+[DEX]"`.

### 3.4 `[HALF_PROF]`

`[HALF_PROF]` есть в `notation.mdx` и `dice-roller.mdx` (половина бонуса мастерства, вниз). В `expression-input.mdx`
и в схеме (числовой контекст) его нет. Схема предлагает `round([PROF]/2)` [схема]. Поэтому `[HALF_PROF]` считать
переменной только костевого контекста, а в числовых полях писать `round([PROF]/2)` [схема, не проверено для `[HALF_PROF]`].

## 4. Заклинания

### 4.1 Что лежит в `spells.prepared` и `spells.book`

Элемент массива может быть одной из форм [док characters.mdx, changelog 2026-10-18]:

1. **id заклинания в базе LSS** — 24 символа hex (ObjectId). Пример: `698197c2a5dc6923c7028c8c` для «Исцеление ран» 2024.
2. **слаг** — английское имя в нижнем регистре через дефис: `cure-wounds`.
3. **английское имя**: `Cure Wounds`.
4. **имя как в базе**: `Исцеление ран [Cure Wounds]`. Имя только по-русски не сводится ни к чему.

Серверная обработка [док]:

- при создании персонажа id остаются в списках, слаги откладываются в `spells.pending`;
- при открытии листа слаги ищутся сначала в SRD редакции персонажа, затем в гримуаре владельца;
- ненайденные показываются в настройках заклинаний и убираются кнопкой «Очистить»; поиск повторяется при каждом открытии.

Списки по назначению [док]:

- `prepared` — известные или подготовленные заклинания, заговоры тоже здесь;
- `book` — книга волшебника; для остальных классов не нужна;
- `granted` — пишет только визард; слаги там не принимаются;
- `slotless` — id заклинаний, оплата которых ячейкой запрещена.

`spellsInfo.charges` и `spellsInfo.abilities` тоже ключуются id заклинания [схема].

### 4.2 Как отличить SRD-заклинание от своего (предложение)

1. Элемент — 24-символьный hex, и он есть в наборе id `srd-spell-slugs-<edition>.json` для редакции персонажа → **SRD**.
   Проверено: наборы id для 2014 и 2024 не пересекаются, поэтому редакцию нужно знать заранее [валид, см. 4.3].
2. Элемент — слаг или английское имя (в скобках или без), и такой слаг есть в файле редакции → **SRD**.
   Английское имя из формы `Имя [English]` извлекается из скобок и приводится к слагу.
3. Иначе — кандидат на **своё** заклинание: искать по слагу или английскому имени в файле гримуара, если он загружен.
   Не найдено — оставить как «не найдено» (аналог `pending`).

Ограничения [не проверено]:

- Форма id своих заклинаний не известна. Вероятно, это тоже 24-hex, но проверить нельзя. Поэтому п. 1 проверяет только
  набор SRD, а не «похожесть» id.
- Не проверено, может ли свой слаг совпасть со слагом SRD.

### 4.3 Файлы слагов (подтверждено фикстурами)

| Параметр | 2014 | 2024 |
|---|---|---|
| Записей | 318 | 339 |
| Формат записи | `{ slug, id, name, level, classes }` | то же |
| `id` | 24-hex, уникальны | 24-hex, уникальны |
| Совпадают `id` между редакциями | 0 | 0 |
| Общие слаги | 313 | 313 |
| Только в этой редакции | 5: `antipathy-or-sympathy`, `blindness-or-deafness`, `branding-smite`, `enlarge-or-reduce`, `feeblemind` | 26: в т.ч. `antipathy-sympathy`, `blindness-deafness`, `enlarge-reduce`, `divine-smite`, `hex`, `ice-knife` (полный список в fixtures) |
| Уровни | 0: 24, 1: 49, 2: 54, 3: 41, 4: 31, 5: 37, 6: 31, 7: 20, 8: 16, 9: 15 | 0: 27, 1: 57, 2: 57, 3: 42, 4: 34, 5: 38, 6: 31, 7: 20, 8: 17, 9: 16 |
| Классы, которых нет среди 12 классов SRD | `artificer`, `shaman`, `magus` | `artificer` |

Факты, которые надо учитывать:

- Имя всегда содержит английское в скобках (проверено: 0 записей без скобок).
- Один и тот же заклинание называется по-разному в разных редакциях: `cure-wounds` — «Лечение ран» (2014) и «Исцеление ран» (2024).
  Сравнивать русские имена между редакциями нельзя; сравнивать по английскому имени или слагу.
- Слаг не всегда одинаков между редакциями. Для трёх пар с «or» в слаге 2014 и 2024 различаются
  (`antipathy-or-sympathy` — `antipathy-sympathy`, `blindness-or-deafness` — `blindness-deafness`, `enlarge-or-reduce` — `enlarge-reduce`).
  Заклинания `branding-smite` (2014) и `divine-smite` (2024) — разные. В доке сказано «Слаг от редакции не зависит» [док characters.mdx].
  Это верно для 313 общих слагов, но не для всех.
- Классы `artificer`, `shaman`, `magus` встречаются в списках заклинаний, но в наборе датасета SRD классов с такими id нет.
  Значит, `info.charClass.id` с таким значением не резолвится в датасете SRD [валид, датасеты].
- В `spells/srd.mdx` сказано «319» заклинаний SRD, а в файле 2014 — 318 [док, фикстуры]. Расхождение.

### 4.4 Гримуар и его экспорт

- Создание: в Гримуаре, раздел «Эффект», поле «Кость» поддерживает переменные `@mod` (заклинательная характеристика) и `@item.level`
  (уровень ячейки). Пример формулы: `1d4 + @mod` [док addition.mdx]. Это Foundry-стиль, а не `[STR]` листа.
- Импорт: в Гримуаре кнопка «.json» → «Загрузить .json» → выбрать файл → выбрать заклинания [док].
- Экспорт: «.json» → «Скачать .json» — файл со всеми созданными и импортированными заклинаниями; его можно использовать для импорта [док].
- Формат: «основан на формате виртуального стола Foundry» [док]. Структура полей (например, `system.*`, `name`, `img`)
  в документации не описана [не проверено]. Слаг и id заклинания видны в карточке, в свёрнутом блоке «Сервисная информация» [док].
  Есть ли они в экспортном файле, не проверено.
- Публичный пример файла экспорта Гримуара: **не найден**. Веб-поиск по «Long Story Short гримуар json Foundry» ничего не дал.
  Конвертер elfrey (1.7 и, по данным поиска, 1.8.4) экспортирует только персонажа и не выносит заклинания отдельным файлом [конвертер, поиск].
  Pet2022 (FVTTtoLSSJsonConverter v1.0.2) экспортирует только подготовленные заклинания, заговоры и заклинания договора;
  формат выходных id/слагов не описан [поиск, README; не проверено].
- Ограничение аккаунта: лимит «Заклинания D&D» — от 120 до 400 в зависимости от роли [док limits.mdx].

### 4.5 Владелец заклинаний

Документация прямо говорит: «Общего каталога у нас нет: у каждого игрока свои заклинания» [док]. Заклинание не из SRD
найдётся только если оно есть в гримуаре того, кто импортирует персонажа. Поэтому при раздаче персонажа с
собственными заклинаниями нужно отдавать вместе с ним и файл заклинаний [док, changelog 2026-08-18].

Тексты собственных заклинаний в файле персонажа **отсутствуют** [док, schema-описание, конвертер].

## 5. Редакции и переводы

### 5.1 `edition` (механическая редакция)

Влияет на данные, а не только на оформление. Различия в датасетах SRD (состав проверен по фикстурам):

| Что | SRD 2014 (5.1) | SRD 2024 (5.2) |
|---|---|---|
| Классы (`classes`) | 12: `barbarian`, `bard`, `cleric`, `druid`, `fighter`, `monk`, `paladin`, `ranger`, `rogue`, `sorcerer`, `warlock`, `wizard` | те же 12 id |
| Подклассы (`subclasses`) | 12; `evocation` (Школа воплощения), `draconic-bloodline` (Драконья кровь), `open-hand` (Путь открытой ладони) | 12; `evoker` (Воплотитель), `draconic-sorcery` (Драконье чародейство), `open-hand` (Воин открытой ладони) |
| Виды (`races`) | 9: `human`, `elf`, `dwarf`, `halfling`, `gnome`, `half-elf`, `half-orc`, `dragonborn`, `tiefling` | 9: `dragonborn`, `dwarf`, `elf`, `gnome`, `goliath`, `halfling`, `human`, `orc`, `tiefling`. Только в 2014: `half-elf`, `half-orc`. Только в 2024: `goliath`, `orc` |
| Подвиды (`subraces`) | 16, в том числе `human-standard`, `human-alternative`, `dwarf-hill`, `halfling-lightfoot`, `gnome-rock`, драконьи `dragonborn-*` | 23, в том числе `elf-drow`, `elf-high`, `elf-wood`, `gnome-forest`, `gnome-rock`, `tiefling-*`, `goliath-*`, драконьи `dragonborn-*` |
| Предыстории (`backgrounds`) | 1: `acolyte` | 4: `acolyte`, `criminal`, `sage`, `soldier` |
| Черты (`feats`) | 1: `grappler` | 6: `alert`, `savage-attacker`, `skilled`, `magic-initiate-cleric`, `magic-initiate-wizard`, `magic-initiate-druid` |
| Слаги заклинаний | 318 | 339 |
| Списки состояний (`conditions`) | зависят от редакции, не перечислены в схеме | то же |

Отдельно по `edition`:

- Бонус-таргеты одинаковы для обеих редакций (один и тот же enum) [схема].
- Id заклинаний не переносятся между редакциями, слаги — почти всегда переносятся (раздел 4.3).
- `sheetEdition` — только печатный лист, на данные не влияет [док].
- Какая редакция по умолчанию применяется, если поле отсутствует: по документации `2024` [док]. Схема здесь не говорит.

Идентификаторы из датасетов — голые: `info.race.id = "human"` в обеих редакциях, но набор видов разный.
Поэтому `race.id` имеет смысл только в паре с `edition`.

### 5.2 `template` (визуальная тема и перевод)

| `template` | Тема/перевод по документации |
|---|---|
| `default` | SRD: перевод проекта «Киборги и Чародеи» (по умолчанию) |
| `hg` | Hobby World (официальный перевод в России) |
| `ph` | PHantom (фанатский перевод) |
| `dndr` | D&D_ru (фанатский перевод) |
| `by` | BY (белорусский) |
| `ua` | UA (украинский) |
| `en` | EN (английский оригинал) |
| `aime`, `aime-pbs` | «Приключения в Средиземье» (Aime) |

Описание схемы: «Visual/label skin. ... Everything else is cosmetic labels, not new mechanics» [схема]. Исключение — aime:
разблокируются `stats.sha`, `saves.cor`, навыки `riddle` и `shadow-lore`, трёхноминальный кошелёк (gp/sp/cp) вместо пяти [схема].

Практический вывод: ключи в данных (навыки, характеристики, таргеты) английские и не зависят от перевода. Перевод влияет на подписи.
Имена заклинаний в базе LSS содержат русское название и английское в скобках; русская часть зависит от перевода (см. 4.3).

## Резюме

- Собственного id персонажа LSS в файле нет (ни в envelope, ни в `data`, ни в примере, ни у конвертера). Для дедупликации нужен другой ключ (раздел 1.1).
- Полный закрытый enum таргетов бонусов есть: 119 значений плюс два открытых семейства `weapon.<id>.attack/damage` по pattern (раздел 2.6.1). Проверено Ajv.
- Envelope: `jsonType`, `version: "2"`, `edition` (по умолчанию 2024), `sheetEdition`, `spells` (`mode`, `prepared`, `book`, `pending`, `granted`, `slotless`), `disabledBlocks`, `data`, `tags` (назначение неизвестно).
- Заклинания в файле — ссылки (24-hex id, слаг, английское имя или `Имя [English]`). Своего текста в файле нет. Своё заклинание находится через гримуар владельца. Публичного примера экспорта гримуара не нашлось.
- Редакция влияет на данные: id заклинаний и подклассов, набор видов, подвидов, предысторий и черт. Слаги почти всегда переносятся, но для трёх пар «or» и нескольких заклинаний — нет.
- Обратный конвертер 1.7 расходится со схемой: числа вместо строк, дробный `isProf`, ключи вне схемы, `text.*.value.id`. Импортёр должен быть терпимым к такому входу.
- Остаётся не проверено: форма экспорта гримуара, форма id своих заклинаний, атрибуты узлов редактора, семантика `bonusesSkills`, `stackingType`, `duration`, и актуальная версия конвертера (1.8.4 не удалось прочитать).
