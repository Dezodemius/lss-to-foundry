# Ручная проверка импорта LSS to Foundry

Состояние на 22.10.2026. Чек-лист для проверки в живой Foundry VTT **13.348** и системе **dnd5e 5.1.8**.
Автоматические тесты (Vitest) покрывают логику без Foundry. Всё, что зависит от живого мира, проверяется здесь.
Foundry при подготовке кода не запускалась и каталог данных не менялся.

Места в коде, которые нельзя подтвердить по исходникам, помечены комментарием `VERIFY IN FOUNDRY`. Список в разделе 8.

## 0. Подготовка

- Foundry 13.348, dnd5e 5.1.8, модуль `lss-to-foundry` подключён (junction или копия в `Data/modules`; это делает пользователь).
- **Тестовый мир**, не боевой. Импорт создаёт актёров, предметы и (при праве) мировые заклинания.
- Настройка мира dnd5e `rulesVersion`: `modern` для персонажей 2024, `legacy` для 2014. Миры для 2014 и 2024 удобнее держать раздельно.
- Babele 2.7.5 и ru-ru 13.348.1 (необязательно). С ними заклинания 2014 придут на русском. Для 2024 русского перевода в ru-ru нет (`docs/research/foundry-module-dev.md` §8.5), английские названия там ожидаемы.
- Пользователи для проверки прав: один с ролью ASSISTANT и выше (`ACTOR_CREATE`, `ITEM_CREATE`), один игрок без них.

## 2. Запуск импорта

- Обычный путь: кнопка «Импорт из LSS» в сайдбаре «Актёры».
- Отладка без окна (макрос, выполняется только в тестовом мире). Путь `modules/lss-to-foundry/...` должен открываться в браузере:

```js
const { importCharacters } = await import('/modules/lss-to-foundry/scripts/foundry/importer.mjs');
// characters и grimoire берутся из результата parseLssFile (окно импорта делает это само)
const report = await importCharacters(characters, grimoire, {
    actorFolder: 'LSS', spellFolder: 'LSS: Гримуар', classFeatures: true, useAvatar: false, extraSpellPacks: [],
}, (p) => console.log('LSS', p));
console.table(report.results.map(({ name, ok, actorUuid, error }) => ({ name, ok, actorUuid, error })));
```

## 3. Лист персонажа: что сравнивать с LSS

Сравнивайте с файлом LSS (экран персонажа в LSS или JSON). Для примера A ожидаемые значения указаны в скобках.

| Что | Где на листе | Ожидание |
|---|---|---|
| Имя, портрет, токен | шапка, токен | имя из `name.value`; портрет только при включённой опции `useAvatar` |
| Характеристики | Abilities | значения LSS + бонусы `stat.<ab>.score` (пример: 13, 10, 14, 10, 16, 12) |
| Спасброски | Saves | владение из `saves.<ab>.isProf` (пример: Con и Wis) |
| Навыки | Skills | владение из `skills.<k>.isProf` (пример: Athletics, History, Insight, Persuasion) |
| Бонус мастерства | Attributes | `proficiency` (пример: +2) |
| Максимум HP | Hit Points | `hp-max + hp-max-bonus + Σ hp.max` (пример: 24 + 3 = **27**) |
| Текущие и временные HP | Hit Points | `hp-current` (пример: 24), `hp-temp` (0) |
| КД | Armor Class | `ac` с учётом щита и бонусов `ac`. Пример A: 10 + DEX 0 + щит 2 + кольцо 1, ожидается 13; сверить с расчётом LSS |
| Скорость, инициатива, чувства | Attributes | `speed`, `initiative`, `darkvision` |
| Спеллкастинг | Spellcasting | характеристика `spellsInfo.base.code` (пример: Wis); СЛ и бонус атаки совпадают с LSS |
| Ячейки 1 круга | Spell Slots | максимум 4, использовано 1 (`value` 3) |
| Ячейки 2 круга | Spell Slots | максимум 2, использовано 0 (таблица dnd5e для Cleric 3 даёт 2 сама, `override` не нужен) |
| Ячейки договора | Spell Slots (Pact) | для примера D: количество и уровень договора |
| Деньги | Currency | `coins.*` |
| Владения | Traits | доспехи и оружие из `prof.*` |
| Состояния | значки на токене, Effects | каждое известное состояние включено |
| Истощение | Token HUD, Effects | уровень из `exhaustion`; эффект `dnd5eexhaustion0` с `flags.dnd5e.exhaustionLevel` |

Если значение не совпадает, сначала проверьте отчёт импорта (раздел 5). Записи «Сверка: ...» показывают расхождение, которое модуль заметил сам.

## 4. Предметы персонажа

- **Вид, предыстория, класс, подкласс**: есть в Items. Во вкладке Details заполнены вид, предыстория и класс (`details.race`, `details.background`, `details.originalClass`). У класса: уровень N, кость хитов из LSS, вкладка Advancement показывает HitPoints и Subclass.
- **Особенности** (`ItemGrant`): ожидаемый набор берётся из компендиума для уровня. Скопированные особенности имеют `flags.dnd5e.advancementOrigin` и `sourceId`. Передаваемые эффекты выключены (`disabled`), их бонусы уже учтены из LSS.
- **Оружие**: атака и урон есть как активности (кнопки броска). Владение и экипировка совпадают с LSS.
- **Ресурсы** LSS: предметы-черты с `uses` (максимум, восстановление).
- **Заклинания**:
  - подготовка: заговоры `prepared` 1; подготовленные `prepared` 1; только книга `prepared` 0; «всегда» `prepared` 2;
  - `method` = `spell` (колдун: `pact`), `sourceClass` = класс персонажа;
  - SRD-заклинания 2014 с Babele на русском, 2024 на английском (ожидаемо);
  - у скопированных предметов нет `flags.babele`. Проверка в консоли: `actor.items.filter(i => i.flags?.babele).length === 0`;
  - у SRD-копий есть `_stats.compendiumSource` (uuid компендиума).
- Предметы из особенностей-заклинаний не появляются (их даёт LSS). Если в отчёте об этом есть строка, проверьте, что заклинание есть в LSS.

## 5. Отчёт импорта

Для каждого персонажа в отчёте: ссылка на актёра, предупреждения, ненайденные и свои заклинания.

- Пример A: предупреждений о классе, виде и предыстории быть не должно (Cleric, Human, Acolyte есть в компендиумах 2024).
- «Сверка: ...» после импорта не должно быть для примера A. Появление такой строки — ошибка сопоставления, её нужно разобрать.
- Ненайденное заклинание: в отчёте пишется его имя или слаг. Предмет не создаётся.
- `ice-knife` (2024) у персонажа 2014: предупреждение о пакете другой редакции. Ожидаемо.
- Мультикласс: строка «Мультикласс не поддерживается». Ожидаемо.
- Выбор особенностей (опциональные гранты): строка «выбор особенностей не перенесён». Ожидаемо, выбор делает игрок на листе.

## 6. Повторный импорт и дубли

- Повторный импорт того же файла создаёт **второго** актёра. Это ожидаемо на этапе 1 (`docs/DESIGN.md` §4.6, обновление появится позже).
- Свои заклинания не дублируются: в папке «LSS: Гримуар» одна запись на каждое заклинание. Оба персонажа (E1, E2) ссылаются на неё через `_stats.compendiumSource`.
- Повторный импорт не создаёт вторую запись того же заклинания в мире.
- Удаление актёра не удаляет мировые заклинания.

## 7. Права

- Игрок без `ACTOR_CREATE`: импорт не запускается, появляется сообщение о праве.
- Игрок с `ACTOR_CREATE`, без `ITEM_CREATE`: актёр создаётся, свои заклинания копируются прямо в персонажа. В отчёте есть строка «мировой предмет не создан, нет права ITEM_CREATE».
- Папки (LSS, LSS: Гримуар) создаются, если пользователь вправе создавать папки. Иначе в отчёте строка «папка ... не создана».

## 8. Места, помеченные `VERIFY IN FOUNDRY`

| Файл | Что проверить |
|---|---|
| `scripts/foundry/compendium-index.mjs` | `pack.getIndex({ fields: ['system.identifier', 'type'] })` даёт вложенный `row.system.identifier` на живом паке |
| `scripts/foundry/compendium-index.mjs` | Babele переводит имя и описание в `getDocument`, `flags.babele` удаляется |
| `scripts/foundry/class-builder.mjs` | `hd.spent` = кости хитов потрачены (уровни минус `hp-dice-current`) |
| `scripts/foundry/spells.mjs` | `prepared` для `innate` (заклинания без ячеек) |
| `scripts/foundry/actor-writer.mjs` | `keepEmbeddedIds: true` на клиенте сохраняет `_id` предметов и эффектов |
| `scripts/foundry/actor-writer.mjs` | производные данные (`system.attributes.hp.max`, `system.spells.*.max`) обновлены к моменту, когда `await actor.update()` вернулся |
| `scripts/foundry/actor-writer.mjs` | эффект истощения `dnd5eexhaustion0` создаётся асинхронно (`_onUpdate` без `await`), проверить после перезагрузки |
| `scripts/foundry/actor-writer.mjs` | `game.modules.get(id).version` возвращает версию модуля |
| `scripts/foundry/importer.mjs` | путь `modules/lss-to-foundry/data/*.json` открывается в установленном модуле |

## 9. Ожидаемые ограничения (не баги)

- Не применяются: опциональные гранты, выбор навыков и владений (`Trait`), `ASI` и `ItemChoice` у вида, класса, подкласса и предыстории. Значения берутся из LSS.
- Заклинания из особенностей не переносятся (их даёт LSS).
- Мультикласс: переносится только основной класс.
- Счётчики, которыми оплачиваются заклинания (`spellsInfo.charges`), не связываются с ресурсами. В отчёте есть строка.
- Формат экспорта Гримуара неизвестен. Чтение защитное, нужен реальный файл «Скачать .json».
- Уровень ячеек договора колдуна задаёт класс. Если он отличается от LSS, в отчёте есть строка.
